# Dodoregis Web App

ระบบลงทะเบียนและติดตามงานทดสอบ (Test Request Registration & Tracking) — Prototype

Stack: **Next.js (App Router) + SQLite (Prisma) + Tailwind CSS**. รันได้ทันทีในเครื่อง ไม่ต้องพึ่ง service ภายนอก

## เริ่มต้นใช้งาน

```bash
npm install
npx prisma migrate dev   # สร้างฐานข้อมูล SQLite (dev.db) ตาม schema
npx prisma db seed       # (ทางเลือก) ใส่ master data + งานตัวอย่าง
npm run dev              # เปิด http://localhost:3000
```

ถ้ารันครั้งแรกและเคยตั้ง DB ไว้แล้ว แค่ `npm run dev` พอ

## คำสั่งจัดการข้อมูล

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run dev` | รัน dev server (ข้อมูลที่กรอกไว้ยังอยู่) |
| `npm run create-user -- <user> <pass> <ROLE> "<ชื่อ>"` | สร้าง/รีเซ็ตบัญชีจาก CLI · ROLE = `ADMIN` \| `ENGINEER` \| `REQUESTER` \| `VIEWER` (ปกติสร้างผ่านหน้า `/settings/users` ได้เลย) |
| `npm run notify` | สแกนงานเลย/ใกล้กำหนด → สร้างแจ้งเตือนในแอป + ส่งออกภายนอก (ตั้ง cron เช้าทุกวัน) |
| `npm run db:clear` | **ลบงานทั้งหมด** (ใบรีเควส/item/runs/report/ไฟล์แนบ/log/แจ้งเตือน) เก็บ master data ไว้ — ใช้เริ่มกรอกของจริง |
| `npx prisma db seed` | ใส่งาน**ตัวอย่าง**กลับเข้าไป (ลบงานเดิมก่อน · master data ถูก upsert) |
| `npx prisma studio` | เปิด GUI ดู/แก้/ลบข้อมูลในตาราง |

> ⚠️ **ข้อมูลที่กรอกในเว็บบันทึกลง `dev.db` จริงและถาวร** — อย่ารัน `npx prisma db seed` หรือ `npx prisma migrate reset` หลังเริ่มกรอกของจริง เพราะจะล้างข้อมูลทิ้ง

## โครงสร้าง: ใบรีเควส → item

```
ใบรีเควส  TR-YYMM-###          ใครขอ (ชื่อ/อีเมล/เบอร์) · test object · วัตถุประสงค์
   ├─ ชิ้นงาน / รุ่น Lamp       เพิ่มได้หลายรุ่น (ชื่อรุ่น · Part No. · จำนวน)
   └─ รายการทดสอบ  -NN         เลือกว่าทดสอบรุ่นไหนบ้าง (ได้หลายรุ่นต่อรายการ)
                               มีแผน / สถานะ / test runs / รีพอร์ท / QR ของตัวเอง
```

- **ชิ้นงาน/รุ่น Lamp อยู่ที่ระดับใบ** — ใบเดียวใส่ได้หลายรุ่น ไม่ต้องพิมพ์ซ้ำในทุกรายการทดสอบ
- **รายการทดสอบติ๊กเลือกรุ่น** ที่จะทดสอบ (หลาย-ต่อ-หลาย) · ระบบสรุปชื่อ/Part No./จำนวนจากรุ่นที่เลือกลง `partName`/`partNo`/`qty` ของรายการให้อัตโนมัติ เพื่อให้ label · CSV · รายงาน ใช้ได้เหมือนเดิม
- **รายการทดสอบไม่บังคับตอนสร้างใบ** — ผู้ขอกรอกมาเองได้เลยหลายรายการ หรือสร้างใบไว้ก่อนแล้วให้ทีมแลปช่วยแตกรายการทีหลังก็ได้ (ทั้งสองกรณีระบบแจ้งเตือนผู้ดูแล)
- ลบรุ่นได้เฉพาะรุ่นที่ยังไม่มีรายการทดสอบใช้อยู่

## ส่งออก CSV — `/api/export?year=YYYY[&month=1-12]&type=…`

ทุกไฟล์เป็น UTF-8 + BOM (เปิด Excel ภาษาไทยไม่เพี้ยน) และมี **ลิงก์กลับเข้าระบบ** ให้กดจาก Excel ได้

| `type` | 1 แถว = | ใช้ตอนไหน |
|---|---|---|
| **`detail`** | 1 รายการทดสอบ (**51 คอลัมน์**) | ข้อมูลดิบหลัก — ทำ pivot ได้ทุกมุมโดยไม่ต้องกลับมาเปิดเว็บ |
| `requests` | 1 ใบรีเควส | ดูภาพรวมรายใบ · ความคืบหน้า · lead time |
| `parts` | 1 ชิ้นงาน/รุ่น Lamp | ตามหาว่ารุ่นไหนถูกเทสในรายการใดบ้าง |
| `runs` | 1 ครั้งที่เทส | วิเคราะห์ retest · pass rate · เวลาที่ใช้ต่อรอบ |
| `dept` / `requester` / `owner` / `month` | 1 กลุ่ม | สรุปพร้อมใช้ (จำนวน · ปิดแล้ว · เลยกำหนด · lead เฉลี่ย · จบตามแผน %) |

**คอลัมน์ใน `detail`** จัดเป็น 9 กลุ่ม: ระบุงาน+ลิงก์ · ใบรีเควส (ผู้ขอ/อีเมล/เบอร์/test object/วัตถุประสงค์) ·
ชิ้นงาน (ชื่อ/part no./จำนวน/รุ่นที่ทดสอบ) · การทดสอบ (ชื่อ/รายละเอียดเต็ม/สถานะ/ผู้รับผิดชอบ/งานด่วน/หมายเหตุ) ·
แผนเทียบจริง (+เลยกำหนดกี่วัน · จบช้ากว่าแผนกี่วัน) · **ที่เก็บ** (วันรับพาร์ท/ที่เก็บพาร์ท/ที่เก็บหลังเสร็จ/raw data) ·
รีพอร์ท (สถานะ/วันส่ง/ผู้จัดทำ/ผู้อนุมัติ/ลิงก์/พาธไฟล์) · ผลทดสอบ (จำนวนครั้ง/ผลล่าสุด/ผู้เทส/ลิงก์ raw data) ·
TAT (lead time · เป้า SLA · สถานะ SLA) · audit (สร้างเมื่อ/แก้ล่าสุด)

## ไฟล์แนบ (อัปโหลด)

- ไฟล์อัปโหลดเก็บบนดิสก์ที่โฟลเดอร์ `webapp/uploads/` (gitignored) — **เก็บเฉพาะ metadata ใน DB** ตามกติกา
- รองรับรูป/PDF/Word/Excel/อีเมล (.eml/.msg)/text · **ไม่เกิน 5MB ต่อไฟล์ และ 20MB ต่อการส่ง 1 ครั้ง**
  (ปรับที่ `MAX_UPLOAD_MB` / `MAX_UPLOAD_TOTAL_MB` ใน `src/lib/workflow.ts` — ถ้าเพิ่มเกิน 20MB ต้องเพิ่ม
  `serverActions.bodySizeLimit` ใน `next.config.ts` ตามด้วย ไม่งั้นอัปโหลดจะล้มเงียบ ๆ)
- ไฟล์ใหญ่ (raw data) ให้เก็บโฟลเดอร์กลางแล้วใช้ "แนบลิงก์" แทน
- แนบได้ **3 จุด**: ตอนลงใบรีเควสใหม่ (ลากวางได้ หลายไฟล์ เลือกประเภทรายไฟล์) · หน้าใบรีเควส · หน้า item
- เปิดดูผ่านเว็บได้ (`/api/attachments/[id]`) — รูป/PDF แสดง inline

## แจ้งเตือน (ส่งออกภายนอก)

`npm run notify` (ตั้ง cron เช้าทุกวัน) จะสร้างแจ้งเตือนในแอป และส่งออกภายนอกถ้าตั้ง env ไว้ (ดู `.env`):
- `NOTIFY_WEBHOOK_URL` — POST `{text}` เข้ากับ Slack / Discord / Teams / Telegram-bridge
- หรือ `LINE_CHANNEL_ACCESS_TOKEN` + `LINE_TO` — LINE Messaging API (LINE Notify ปิดบริการ เม.ย. 2025 แล้ว)

**ผูก LINE OA:** ทำที่หน้า `/settings/line` — มีคู่มือครบ (สร้าง Messaging API channel → ออก token → หา userId/groupId) + ปุ่มทดสอบส่ง (ยิงจริงถ้าตั้ง token แล้ว หรือ dry-run โชว์ payload ถ้ายัง)

การเปลี่ยนสถานะจะสร้างแจ้งเตือนแบบเรียลไทม์ในแอปเสมอ · bell ใน NavBar แสดงจำนวนที่ยังไม่อ่าน

## กติกาบังคับกรอกตามสถานะ (validate ใน `src/lib/workflow.ts`)

- เข้าสถานะ **3-รับพาร์ทแล้ว** ต้องมีวันที่รับพาร์ท + ตำแหน่งเก็บพาร์ท
- เข้าสถานะ **7-ส่งรีพอร์ทแล้ว** ต้องมีรีพอร์ทที่มีวันที่ส่ง + ลิงก์รีพอร์ท
- เข้าสถานะ **8-ปิดงาน** ต้องมีที่เก็บชิ้นงานหลังเสร็จ + ที่เก็บ raw data

## QR label — 2 โหมด (`QR_MODE` ใน `.env`)

| โหมด | ใน QR มีอะไร | สแกนยังไง | URL เปลี่ยนแล้วต้องพิมพ์ใหม่ไหม |
|------|--------------|-----------|---------------------------------|
| **`code`** (ค่าเริ่มต้น) | รหัสงานล้วน เช่น `TR-2607-001-01` | ผ่านหน้า **`/scan`** ในแอป (เปิดกล้อง → เด้งเข้าหน้างาน) | **ไม่ต้อง** — QR นิ่งตลอดไป |
| `url` | URL เต็ม เช่น `https://โดเมน/items/TR-2607-001-01` | กล้องมือถือปกติได้เลย | ต้องพิมพ์ใหม่ (แต่หน้า `/scan` ยังอ่าน label เก่าได้ เพราะตัดโดเมนทิ้ง) |

- ค่าเริ่มต้นคือ **`code`** — เหมาะกับ label ที่ติดชิ้นงานถาวร ย้ายเซิร์ฟเวอร์/เปลี่ยนโดเมนกี่รอบก็ใช้ QR เดิม
- จะสลับเป็น URL (เมื่อมีโดเมนถาวรแล้ว) ให้ตั้ง `QR_MODE=url` ใน `.env` แล้ว build/restart ใหม่
- โหมด `url` ต้องตั้ง `APP_BASE_URL` เป็น URL ที่มือถือเข้าถึงได้ด้วย (เช่น `http://192.168.1.10:3000` — LAN IP ของเครื่องที่รันเว็บ ดูได้จากบรรทัด "Network" ตอน `npm run dev`) ไม่งั้นจะฝัง `localhost` ซึ่งมือถือเปิดไม่ได้
- หน้า `/scan` อ่านได้ทั้ง 2 รูปแบบ (รหัสล้วน และ URL เต็มของโดเมนใดก็ตาม) → label เก่าที่พิมพ์ไปแล้วยังใช้ได้เสมอ
- ⚠️ กล้องเปิดได้เฉพาะเมื่อเปิดเว็บผ่าน **https หรือ localhost** (ข้อจำกัดเบราว์เซอร์) — บน LAN http กล้องจะถูกบล็อก ให้ใช้ช่องกรอกรหัสแทน หรือครอบด้วย Cloudflare Tunnel

## หมายเหตุด้านเทคนิค

- ใช้ Next.js 16 + Prisma 7 (`prisma-client` generator แบบ ESM, ต้องใช้ driver adapter — โปรเจคนี้ใช้ `@prisma/adapter-better-sqlite3`)
- ไฟล์แนบทุกชนิดเก็บเป็น **ลิงก์ (url)** เท่านั้น ไม่มีการอัปโหลดไฟล์เข้า database
- QR code สร้างฝั่ง server ด้วย `qrcode` — ดูโหมดที่ `src/lib/qr.ts` (`QR_MODE`); โหมด `url` อิง `APP_BASE_URL` หรือ host ของ request
- **Auth**: รหัสผ่าน bcrypt + session เป็น cookie เซ็น JWT ด้วย `jose` (httpOnly, 8 ชม.) — ตั้ง `AUTH_SECRET` ใน `.env` (สร้างอัตโนมัติแล้ว) · สิทธิ์บังคับที่ `src/lib/guard.ts`
- **UI kit ภายใน**: `components/ui/Feedback.tsx` (toast + กล่องยืนยัน — เลิกใช้ `window.confirm`) · `components/ui/Icon.tsx` (ไอคอน SVG ชุดเดียว)
- **ติดตั้งเป็นแอปบนมือถือได้ (PWA)** — `src/app/manifest.ts` + `public/icon.svg` มีทางลัดตรงไปหน้าสแกน
- Mobile-first: แถบเมนูล่าง 5 ช่องบนมือถือ (แถบบนเป็นของเดสก์ท็อป), ปุ่มสูงอย่างน้อย 44px, ตารางเลื่อนแนวนอนได้
- ⚠️ eslint ของโปรเจคห้ามเรียก `setState` ตรง ๆ ใน `useEffect` (`react-hooks/set-state-in-effect` เป็น **error**) — ให้ derive ค่า, ย้ายไป event handler หรือใช้ `useSyncExternalStore`
